# Audit — 2026-09-07

## Baseline and method

Started from a clean `main` at `14ca84dc96d4f4991c4e9c3c40f348d2c8b4e503`, matching `origin/main` and annotated `v0.12.3`. Architecture and release procedures were read from the current README, changelog, all `docs/` files, Makefile, frontend package configuration, Go module, Dockerfile, Compose configuration, and both workflows. No repository `AGENTS.md` was present; the user-supplied instructions applied. No existing changes were overwritten.

The application is a static SvelteKit frontend served by Go, with REST intent commands, personalized WebSocket snapshots, SQLite WAL and one database connection. Playback has a separate revision. YouTube is loaded through the shared IFrame API loader using `youtube-nocookie.com`. Optional oEmbed and hash-prefix SponsorBlock lookups run on the server. The server, rather than an iframe or a tab, owns durable state.

The final frontend build contains 24 JavaScript assets totaling 373,624 uncompressed bytes, including lazy routes and shared chunks; this is not the initial page transfer size. The room route is 62,355 bytes. No dependency or speculative micro-optimization was added.

## Findings

| Priority | Reproduction and impact | Resolution and regression |
| --- | --- | --- |
| P1 | Join an unlisted room, then change it to private. The existing uninvited socket remains subscribed and `player.play` still succeeds. | Current eligibility filters snapshot recipients and is checked in the command transaction. `TestRestrictedRoomRevokesExistingMemberAccess` failed before the fix and passes afterward. |
| P1 | Revoke an invitation while its viewer is connected. Commands and future snapshots remain available. | Invitation removal refreshes access and disconnects the viewer. `TestRevokedInvitationDisconnectsExistingViewer` reproduced both failures. |
| P1 | Remove/block a friendship after joining a friends-only room, including as admin. Room library and preview still disclose current private media. | Shared eligibility predicate protects metadata responses and socket fan-out. `TestFriendRemovalRevokesAdminRoomAccess` covers remove/block, admin restrictions, library and preview filtering. |
| P1 | Command authorization was read before `BeginTx`; a permission change could commit between the check and a playback command using an unchanged playback revision. | Capability and eligibility checks now use the same transaction as the mutation. Existing permission, playback revision, and race regressions pass. |
| P1 | Invitation POST checked the manager role before reading its body; a manager demoted during a slow upload still received 204 and created the invitation. | Decode before locking, then authorize and read/write invitations in one transaction. `TestInvitationAuthorizationAfterSlowRequestBody` deterministically reproduced the unauthorized insert. Membership departure also checks the owner role in its deletion transaction. |
| P2 | Anonymous owners could change visibility to private/friends-only and then fail to rejoin with `account_required`. | Every account-only visibility requires an account-linked owner. Both cases failed before the fix in `TestAnonymousOwnerCannotLockThemselvesOut`. |
| P2 | Snapshot room revision was read separately from playback, queue, permissions and activity; concurrent commits could produce mixed state. | One read transaction. `TestSnapshotKeepsConcurrentRevisionAndPlaybackConsistent` checks 100 reads against 100 concurrent transactional updates. |
| P2 | `KOALAPARTY_PRODUCTION=true` accepted `KOALAPARTY_E2E=true`, exposing unauthenticated shutdown and relaxed creation limits. | Configuration rejects the combination before opening the database. `TestProductionRejectsE2EMode` failed before the fix. |
| P2 | HTTP paths included account usernames, session hashes and arbitrary identifiers; background panic messages included raw room IDs. | Registered route patterns and hashed room labels only; no arbitrary panic payload. `TestRequestLogsExcludeDynamicIdentifiers` reproduced the HTTP disclosures. |
| P2 | Real YouTube in a second tab remained UNSTARTED without autoplay permission. The watchdog replaced the sound-preserving gesture with an error. | Watchdog preserves an already detected autoplay block. A new browser regression runs the clock for 21 seconds and verifies the gesture remains usable with zero mute calls. |
| P2 | Real reload with `jNQXAC9IVRw` requested after its 19.021-second duration stayed at zero in BUFFERING indefinitely. Stable-state-only end detection never ran. | The initial load anchor and matching video metadata now allow terminal recovery before stable timeline checks. The reload regression covers both PLAYING and persistent BUFFERING. |
| P2 | Firefox trace showed the shrinking sticky header intercepting the autoplay action during global smooth scrolling. | Removed global smooth scrolling and added 92-pixel top scroll padding. The gesture regression also checks header clearance before an ordinary click. |
| P2 | Real terminal-reload diagnostics alternated PLAYING/BUFFERING and `authoritative_sync` several times per second. The Svelte effect implicitly subscribed to local state read by diagnostic helpers. | Explicit server inputs and readiness drive the effect; `untrack(sync)` excludes local callback state. A third reload regression models asynchronous BUFFERING/PLAYING callbacks after every seek. |
| P2 | CI allowed one Playwright retry, and two large WebKit scenarios exceeded their shared 45-second test budgets. | Retries are zero. Trace showed progressing operations until the overall deadline; independent scenarios were split while retaining their assertions and original timeout. Targeted run: 18/18 across all engines. |
| P3 | SQLite playback timestamps have second precision, so a newly extrapolated anchor can include subsecond rounding error. | Retained for this patch; bounded by existing drift correction. A fractional-timestamp migration requires a separate compatibility change. |
| P3 | Admin statistics query current titles once per active room. | Retained: low-frequency, authenticated administration path. A batch query is a future optimization; no room-wide performance gain is claimed. |

Private ownership transfer was also tested against the stricter access checks. Because the existing operation retains the old owner as admin, it now retains their private invitation. Friends-only rooms continue to use the new owner's friendship policy.

## Verification

Baseline: frontend 100 unit tests; type check had zero errors and warnings. Final local gates and publication details are captured in the delivery report. Audit logs are retained under the ignored `.cache/audit-*` paths, including full browser output, JSON Go results and Docker build output. Failures were investigated and preserved in the report rather than counted as passing runs.

- Backend: `gofmt -l .` empty; `go test -count=1 -json ./...` and `go test -race -count=1 -json ./...` each pass 83 tests including subtests; `go vet ./...` passes.
- `go run golang.org/x/vuln/cmd/govulncheck@latest ./...`: zero vulnerabilities in called symbols or imported packages. Four advisories exist in required modules outside the application's called code; these are not reported as reachable vulnerabilities.
- Frontend: `npm run check` reports zero errors/warnings; `npm run lint`, 100 unit tests in nine files, optimized production build, and `npm audit --audit-level=high` pass. npm audit reports zero vulnerabilities.
- `node --test scripts/*.test.mjs`: 3/3; `git diff --check` passes.
- Docker: final local image built successfully; container runs as `koala`, becomes `healthy`, and returns successful `/api/ready` and `/api/version`. Own smoke containers were stopped normally and removed. Docker Desktop and the engine were not started, stopped, killed or reset.
- The final complete browser run passes all 18 scenarios across Chromium, Firefox and WebKit (54/54, 4.6 minutes), no skips and zero configured retries. Release publication additionally requires green CI and release verification on the exact commits.

One complete Windows run finished with 53 passes and one initial-page failure. Its Chromium trace records `net::ERR_NO_BUFFER_SPACE` for the application entry module before the registration form existed. The failed run was preserved as `.cache/audit-e2e-host-buffer-failure.log`; it was not attributed to an account-command failure. Own real-browser and container tests were then closed before repeating the complete suite without parallel build/video load. Automatic retries remain disabled.

## Deferred product work and limits

- P2, medium effort: full per-capability editor and ban list. Server enforcement exists; expanding management UI needs its own accessibility and multi-role review.
- P2, high effort: trusted server-side end detection. The current provider cannot authoritatively report iframe duration or completion to the server; at least one eligible browser must report a natural end. Additional metadata/provider dependencies change privacy and reliability assumptions.
- P3, high effort: PostgreSQL/event-bus scaling and a reproducible load benchmark. The current deployment is deliberately single-instance; no horizontal scaling or soak-test claim is made.
- P3, medium effort: physical Mobile Safari fullscreen, hardware Media Session and assistive-technology matrix. Desktop WebKit automation does not substitute for those devices.
- Autoplay is a browser policy. The app never silently mutes; a tab without permission needs an explicit sound-preserving gesture.
